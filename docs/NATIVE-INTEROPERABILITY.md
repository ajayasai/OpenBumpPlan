# Native interchange and independent logical intent — v0.4.0

This release adds native KiCad **terminal-map** interchange and independent logical connectivity review. It is not a full board converter or evidence of superiority over every commercial EDA product.

## Run

`npm start`, then open `http://127.0.0.1:4173/interop.html`, or use the planner's **Interoperability** link. `npm run build` also creates the self-contained `dist/interop.html`. No external runtime dependencies or network requests are used by either application. Load the planner's local saved project explicitly, or transfer project JSON files; the workbench never writes over the planner's local project automatically.

The synthetic example's contract is provided to demonstrate the workflow, not as independent approval. Real contracts must originate in separately reviewed design intent. **Generating intent from a possibly wrong map cannot prove that map correct.**

## Import and export boundaries

The bounded S-expression reader supports modern `.kicad_pcb` boards and `.kicad_mod` footprints containing simple SMD circle, rectangle, oval or rounded-rectangle pads on front/back copper. It preserves terminal references/numbers, explicit net labels, absolute XY positions and pad geometry metadata. KiCad millimetres/y-down are converted to package micrometres/y-up. Footprint rotation is applied; already-flipped back-side local coordinates are not mirrored a second time. Duplicate selected references, repeated physical pin numbers, mismatched net codes, malformed numbers, unsupported pad types/geometry and exhausted parsing budgets are rejected.

Tracks, vias, zones, drawing geometry, outline, stackup, physical rule settings and 3D models are not imported. Reference filtering explicitly reports omitted footprints. Pads remain point sites for the planning engine; retained native metadata does not turn geometric proxies into copper signoff. Imported voltage domains are unknown, not invented.

Export requires an explicit round-pad diameter, site kind and copper side. Selected sites are flattened into package XY. An **unrouted** native board carries net assignments; a library footprint deliberately carries no net assignments. A mapping receipt binds source identity and generated bytes. Duplicate output pad numbers, connected net-name conflicts and assigned reserved/no-connect sites are rejected. Coordinates are emitted at 1 nm resolution; diameters must be representable at that resolution.

`verify-export` requires an independently supplied original project and explicit expected geometry. It re-reads actual board terminals and compares their number, reference, footprint name, net, side, position and dimensions. It does not trust receipt maps, counts or pass flags. Added non-terminal copper/content cannot pass this unrouted-map verification. Reformatting is not a manufacturing check; arbitrary native boards must not be treated as approved outputs merely because terminal labels match.

Capacity is bounded at 10,000 project sites and 5 MiB input. The workbench's diagram displays at most 3,000 sites/links with an explicit message; no sites are downsampled for verification or export. Large-workbench operations currently execute on the UI thread, unlike the existing planner's worker-based solvers; this is not an interactive-latency qualification.

## Independent connectivity contract

```json
{
  "schema": "openbumpplan.connectivity-contract/v1",
  "name": "Separately reviewed interface intent",
  "coverage": "all",
  "nets": [{"name": "DATA", "ports": ["pad:DATA", "ball:A1"], "domain": "V1"}],
  "unassigned": ["ball:spare"]
}
```

Each terminal appears at most once. `all` coverage requires every project terminal to be explicitly assigned or unassigned. `listed` coverage checks only the specified intent and is marked limited; it cannot authorize an ECO. A separate undirected graph traversal detects missing terminals, uncovered sites, opens, shorts, contradictory node/edge net declarations, reserved/NC connections and explicit domain mismatches. Equal names alone never establish connectivity. Work-limit exhaustion is incomplete/failing, not an all-clear. Findings are capped with an explicit total/truncation indicator.

An intent review can be replayed against an independently supplied project and contract. Hashes are integrity identifiers, not signatures or authority approval. Existing Ed25519 physical review-bundle signing remains in the main CLI; the new logical review itself does not add identity authentication.

## Atomic mapping-only engineering changes

A `mapping-eco/v1` patch binds the complete normalized base project SHA-256 and the separate contract SHA-256. Every edited edge also specifies its expected from/to/net values. Only target reassignment is supported. Missing/duplicate edges, stale bases, changed intent and locked endpoints/mappings are rejected. The complete candidate must pass current hard planning rules **and** an all-port intent contract before it can be applied. No force mode weakens constraints. Preview does not modify the project; Apply is explicit, rechecks the candidate and supports one-step Undo in this workbench.

```sh
node scripts/interop.mjs import package.kicad_pcb imported.json --reference U1 --kind pcb
node scripts/interop.mjs export examples/interop-project.json pinmap --diameter 250 --kind ball
node scripts/interop.mjs verify-export examples/interop-project.json pinmap.kicad_pcb pinmap.receipt.json --diameter 250 --kind ball
node scripts/interop.mjs check examples/interop-project.json examples/interop-contract.json intent-review.json
node scripts/interop.mjs replay examples/interop-project.json examples/interop-contract.json intent-review.json
node scripts/interop.mjs eco examples/interop-swapped.json examples/interop-repair.json examples/interop-contract.json repaired.json
```

CLI writes refuse existing output paths. Exit 0 denotes a completed passing operation, 1 a failed verification, and 2 an input/usage error. Failed ECO candidates are not written as projects. Keep backups; multi-file export is not a filesystem transaction if an external process races the output writes.

## Correctness and release fixes

The continuous-copper checker now rejects boundary contact independently of numerical clearance slack. Changing clearance from zero to a tiny positive number must not turn touching/slightly overlapping copper into a pass. The regression covers contact, overlap, tiny positive clearances and separated controls. The existing conservative spatial index and its work budgets are retained.

Obsolete one-off compressed import workflows are removed from the new branch; their original versions remain in Git history. The temporary delivery workflow uses bounded decompression before JSON materialization. Newly created review bundles are recomputed for v0.4.0, not relabeled or presented as old signatures.

## Reproduce checks

`npm test` runs all retained and new Node suites. `tests/interop_browser_test.py` runs the real HTML, downloads, stale-result rejection, atomic changes and independent CLI replay. `--native` adds a real localhost-origin storage scenario. `tests/kicad_native_test.py`, run using a Python interpreter with the actual KiCad `pcbnew` module, compares pad coordinates/nets against native parsing on both copper sides and non-right-angle rotations, round-trips KiCad's own serialization, loads emitted library footprints and checks a complete 10,000-pad board. It records the actual KiCad version. These are interoperability tests, **not** commercial head-to-head benchmarks or PCB DRC.

CI evidence is written to `OPENBUMPPLAN_EVIDENCE_DIR` when set, avoiding changes to frozen release reports. `scripts/refresh-release.mjs` is a maintainer packaging command, not a verification command; `npm run verify:release` checks the frozen manifest without regenerating it. Historical validation records are retained.

## Format references and competitive scope

Implementation references: KiCad's official [S-expression board format](https://dev-docs.kicad.org/en/file-formats/sexpr-pcb/) and [common syntax/pad definitions](https://dev-docs.kicad.org/en/file-formats/sexpr-intro/). The native oracle does not use this implementation's coordinate transform to compute its expected positions.

Cadence Integrity System Planner documents direct Allegro database interoperability, and Siemens Xpedition Substrate Integrator documents system connectivity verification. A tested KiCad terminal adapter is useful progress in open interoperability; it is not equivalent native integration with every commercial format. Full LEF/DEF, IPC-2581, ODB++, proprietary databases, industrial qualification and validated SI/PI/thermal/mechanical analysis remain outside this release.
