# v0.3.0 engineering semantics

## Certified sparse assignment

`sparseAssignmentProblem` constructs all unary-compatible source/target arcs in the selected stage. It honors fixed/locked assignments, explicit target metadata, local keepouts, source subsets and maximum L1 length. It does not silently drop arcs to enforce an arbitrary nearest-neighbour count. The graph, scope and original project content are SHA-256 bound. Audit/revision metadata are excluded from the optimization graph identity; substantive project changes invalidate it.

The objective is the sum of `round((L1 + changed-target penalty) / quantum)`. Default quantum is 0.001 µm. For n assignments, quantization changes any assignment's unrounded objective by at most n*quantum/2. An integer optimum need not be the exact unrounded optimum; the resulting unrounded suboptimality is at most n*quantum when comparing the same feasible set. Geometric hard-rule comparisons still use floating-point model semantics.

Successive shortest augmenting paths use integer potentials and nonnegative reduced costs. Magnitudes are bounded so integer path/potential/total calculations remain in the exactly representable range of JavaScript numbers. `checkIntegerMatching` does not invoke the solver: it checks assignment cardinality, capacity, original allowed arcs, claimed total, and all residual edge inequalities. A feasible residual potential proves the absence of any cost-improving residual cycle. A Hall certificate names a source set with a strictly smaller full neighbourhood.

`optimizeScalable` additionally evaluates every configured hard rule and locked downstream signal. A relaxed optimum that is hard-feasible is also optimal among hard-feasible assignments for that same integer objective. A relaxed optimum that fails hard rules is rejected, not applied and not called hard-constrained infeasibility.

## Coupled search with replayable coverage

`optimizeCoupledScalable` removes the 12-source permutation restriction by solving a sparse assignment relaxation at each search node. It uses best-first lower bounds and a hard-rule oracle. After rejecting a complete assignment, the remaining assignments are partitioned by the first source whose target differs: earlier targets are fixed, and the differing source's current target is excluded. These prefix children are disjoint and cover all remaining assignments. A child whose differing row has only the excluded arc is trivially empty and omitted.

`verifyCoupledProof` reconstructs the original graph, verifies each relaxed certificate, recomputes hard-rule rejection and locked-signal preservation, and reconstructs the children itself. It never trusts a producer-supplied list of children or a producer's all-clear flag. A feasible incumbent is optimal only when every unresolved partition's proved lower bound is at least its objective. Exhaustive infeasibility requires no incumbent and no unresolved partition. Incomplete geometry analysis cannot exclude a candidate.

The search can still be exponential. Limits: 128 certified subproblems, 20,000 frontier nodes, 20 million edge-record units, at most 60 seconds of search, and the underlying project's 10,000-site safety limit. Candidate construction defaults to 250,000 arcs / 5 million candidate examinations; explicit caps can increase these to 1 million / 20 million. Resource exhaustion is unknown or feasible-with-bound, never a fabricated proof. Certificate replay adds work beyond the search timer, is itself bounded, and can reject an overlarge proof. Benchmarks report end-to-end engine time including replay.

The old exact solver remains available for a different crossing-weighted score and `maxChanges`. The new solvers do not implement that max-change cardinality cap; source subsets and per-change penalties are supported. Stages and physical coordinates outside the selected mapping remain fixed. This is not joint die-placement/routing/physics optimization.

## Negotiated routing

The earlier multi-order sequential A* remains the baseline. Negotiated search begins with a bounded baseline attempt, then rips up each prior route, permits temporarily penalized route conflicts, and updates occupancy/history costs. A complete final grid witness must pass `verifyRoutes`; a temporary collision cannot be promoted to a valid result. Routing remains heuristic and failure is not an unroutability proof.

The 100-case corpus uses fixed seeds 1–100, not only favorable cases. The separate seed-10 demonstration was selected to expose a previous limitation and is labelled as a regression example. Improving route completion can require more total length, vias or computation. No global route-length optimum is claimed.

## Continuous finite-width geometry

`verifyCopper` deliberately does not import the router, rasterizer, cell halo or grid verifier. It shares canonical project validation/transforms, but computes its own geometry: collinear orthogonal segments become round-capped capsules; adjacent-layer vias and pads are circular discs in each relevant layer; rectangular keepouts are transformed independently. Continuous Euclidean distances are compared against radii plus clearance. Zero-clearance copper contact is still a collision. Terminal coordinates, route steps, coverage, lengths, pair mismatch and metrics are recomputed.

The technology object is mandatory, explicitly in micrometres: traceWidth, viaDiameter, padDiameter, clearance. These are uniform simplified dimensions. Active and reserved/NC sites conservatively block columns through routing layers, apart from a route's own terminals. Same-stage finite pads are also checked against each other. This may reject a physically realizable design and does not claim process-deck completeness. Via enclosure, detailed pad stacks, z-distance, impedance, current density, pair coupling, dielectric properties and return paths are not represented.

`routePhysical` inflates the search grid conservatively, then requires both independent checks. It never reduces a technology dimension to obtain a pass. The default safety ceiling is two million continuous comparisons; incomplete checks fail closed.

## Evidence and trust

Physical review bundles bind technology and recomputed copper findings. Verification can require a separately supplied expected technology to detect substitution with easier assumptions. Without that external contract, verification establishes consistency under the included assumptions, not their suitability. Trusted-key Ed25519 verification authenticates the manifest, not foundry approval or organizational authorization. Wrong/malformed keys clear planning, routing and copper pass flags.

Optimization reports include the original input project in the browser export. CLI proofs must be verified against the original project, not the newly assigned output. Changing source subsets, target sets, costs, penalties, dimensions or substantive model content invalidates the corresponding claim. Proof verification and signing are local operations; no private keys are shipped.
