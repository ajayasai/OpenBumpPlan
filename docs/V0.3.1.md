# v0.3.1 — indexed independent copper validation

## Algorithm and invariant

`verifyCopper` still constructs axis-aligned trace capsules, via discs and terminal pads in physical micrometres, checks declared technology, validates project rules and independently checks the supplied route coordinates. It does not trust a stored `verified` flag or the router's rasterization.

A deterministic binary bounding-volume hierarchy indexes centerline boxes. Each internal node encloses all descendant centerlines and records the **maximum** descendant radius. If either coordinate gap between a query box and that enclosing box exceeds the query radius plus maximum radius plus clearance/tolerance, every descendant is too far away to fail the existing distance test. Only then is the subtree skipped. Inclusive candidate comparisons and an outward floating-point allowance retain boundary contact. Every surviving candidate still goes through the original Euclidean box-distance test and trace/via/pad radius rule. This is not nearest-k pruning.

Layer-specific indexes filter copper pairs; a separate index filters keep-out/pad obstacles; another filters terminal-pad pairs. Results are sorted by original index, retaining the old diagnostic ordering and 1,000-detail truncation policy. Final complete/failure decisions and geometry metrics remain unchanged when both algorithms complete.

The broad phase does not certify foundry manufacturing rules. Physical assumptions, conservative all-layer obstacle treatment, same-connection exclusions and tolerance semantics are unchanged from the preceding checker. Arbitrarily dense or overlapping geometry can still require quadratic candidate work.

## Work limits and evidence compatibility

`maxComparisons` defaults to 2,000,000 and may be 1–10,000,000. New `maxSpatialVisits` defaults to 10,000,000 and may be 1–50,000,000. Invalid or unknown options fail closed. Exceeding either budget returns `ok:false, complete:false`; a stopped check is never accepted. The spatial counter counts construction entries, bound-building visits, tree nodes and leaf entries; it is not a CPU-instruction, memory or wall-clock limit. Sort operations are not separately counted.

Results expose `algorithm: "aabb-bvh-v1"`, `comparisons` and `spatialVisits`. These fields are part of recomputed review evidence. The engine version is therefore **0.3.1**, and the example reviews are explicitly reissued. An earlier bundle or external signature is not silently upgraded: use its original versioned verifier or create and approve a new review. Hash-only replay still does not authenticate a publisher; signatures require an independently trusted public key.

## Tests and benchmark scope

The frozen v0.3.0 test oracle uses the old X sweep and full obstacle/pad loops; it never imports the new index. One hundred randomized boards compare all semantic output fields and ordered findings, excluding only the changed performance counters. Forty randomized box sets, floating-scale boundary cases, malformed inputs and independent budget exhaustion exercise conservative filtering. Adversarial witness mutations test endpoints, layers, loops, missing routes, dimensions, metadata and transformed keep-outs.

`npm run qualify:copper` generates deterministic separated L-shaped witnesses, performs one unmeasured warm-up followed by five alternating-order samples per algorithm, retains every raw sample and input SHA-256, and asserts equivalent results whenever the preceding algorithm completes. No route-generation success is implied. A dense oversized-copper mutant must still fail, and both budgets must fail closed.

The 512-route, 8,192-site case includes many unused reserved-pad obstacles; it passes the existing grid checker, continuous checker, review creation and independent full replay. The 1,024- and 4,096-route cases exercise **only supplied-witness copper checking**. The router/grid-checker cap remains 512. Incomplete old runs cannot be compared as equivalent-work timings or used to compute speedup ratios.

No commercial EDA system was executed. No industrial board or package was qualified. This update does not add native proprietary databases, electrical/thermal/stress analysis, foundry DRC, manufacturing qualification, multi-user access control or larger route-generation capacity.

## Reproduce

```sh
npm test
npm run build
npm run verify:release
npm run qualify:copper
node scripts/cli.mjs verify-copper examples/routing-laboratory.json examples/physical-routes.json --technology examples/copper-technology.json
node scripts/cli.mjs verify-bundle examples/physical-review.json --project examples/routing-laboratory.json --technology examples/copper-technology.json
```

The benchmark writes a fresh environment-specific report. Preserve the retained report before rerunning when exact release-manifest verification is required. CI sends rerun output to its own artifact instead of changing retained evidence.
